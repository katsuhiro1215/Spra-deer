# Spruと鹿。— 足元には、ご用心。

「うんこを避けた先の、安全そうな道にも罠がある」を試す、縦画面の第1ステージです。既存の3サンプルと同じ Phaser + TypeScript + Vite を使い、`deercleansample` を参考に720×1280の縦画面にしました。

## 起動

Windowsでは、このフォルダの **`start-game.cmd` をダブルクリック**します。Viteが起動したら、ブラウザで **http://localhost:5178/** を開いてください。停止は起動したウィンドウで `Ctrl+C`。

WSLのNode.js / npm（nvm）が設定済みであることを前提にしています。別の環境では、Node.js 22.12以上（推奨24）を用意し、このフォルダで実行します。

```sh
npm ci
npm run dev
```

`index.html` の直接ダブルクリックでは動きません。5178番が使用中の場合は、そのサーバーを確認してから停止してください。このゲームは既存のサーバーを自動終了しません。

## 操作

| 操作 | スマートフォン / マウス | キーボード |
|---|---|---|
| 移動 | 左パッドまたはゲーム画面を押してドラッグ | 方向キー / WASD |
| 止まる | 指を離す | キーを離す |
| ジャンプ | 右下のジャンプボタン | Space |
| 一時停止 / 再開 | 右上の一時停止ボタン / つづきから | Esc |
| 再挑戦 | 結果画面の「すぐに、もう一回」 | R |

左右の2本指で、移動しながらジャンプできます。右下の「音 OFF」で効果音をオンにできます。別タブや別ウィンドウへ移ると自動で一時停止します。

## 第1ステージの遊び

- スタートから公園の上へ進み、旗のあるゴールへ向かいます。自動前進ではないため、立ち止まって道を観察できます。
- 鹿のうんこを踏むとゲームオーバー。Spruの**足元の影**が接触位置です。体の絵が少し重なっても、足元が触れなければ通れます。
- うんこのすきまの先に、3か所の崩れる床があります。ひびが手がかり。接近すると「ミシッ…」と揺れ、その後に穴になります。
- 予兆を見て止まる、横へ回り込む、適切な位置から跳び越えることができます。ジャンプ中も床の仕掛けは作動し、穴へ着地すると落ちます。
- 失敗してもすぐに再挑戦できます。うんこと罠は固定配置なので、場所とタイミングを覚えて上達できます。
- クリアタイムと自己ベストを表示します。自己ベストはこのブラウザのlocalStorageに保存します。共有ランキングではありません。

第2〜10ステージ、突然現れる壁、倒木、外部ランキングはまだ実装していません。まず第1ステージの操作感と「もう一回」の面白さを確認する試作品です。

## 構成と調整箇所

| ファイル | 役割 |
|---|---|
| `src/game/stage.ts` | スタート・ゴール、うんこ・罠の配置、速度・ジャンプ・予兆時間 |
| `src/game/world.ts` | 固定120Hzの移動・ジャンプ・衝突・罠・勝敗判定 |
| `src/view.ts` | Phaserの公園、カメラ、キャラクター、ひび・崩壊・落下の演出 |
| `src/input.ts` | キーボード、ドラッグ、複数指タッチ |
| `src/main.ts` | タイトル・プレイ・停止・結果、タイム保存、効果音 |
| `src/styles.scss` / `index.html` | 縦画面と操作UI、PCの案内 |

第1の床は予兆0.65秒、第2は0.76秒、第3は0.72秒です。三つとも、予兆に気づいてから止まれる位置で発動します。まずここを調整すると難易度が変わります。

キャラクター画像4点は `../deersample/public/assets/` からそのままコピーしました。描画時だけ透明余白を除き、画像自体は変更していません。公園・床・うんこはコード描画です。Blender、外部画像API、CDNは不要です。既存の3サンプルとtricycleのコードは変更していません。

## 検証

```sh
npm test
npm run build
```

実ブラウザの操作検証は、別ターミナルで `npm run dev` を起動してから実行します。

```sh
# この環境には既存のWSL用Chromiumがあります。
# 別環境で初めて使う場合のみ: npx playwright install chromium
npm run test:browser
```

必要なら `PLAYWRIGHT_CHROMIUM_EXECUTABLE` に既存のChromiumの実行ファイルを指定できます。`GAME_URL` で検証先を変更できます。スクリーンショットは `test-results/` に保存されます。

ブラウザテストは入力操作で開始・移動・ジャンプ・失敗・再挑戦・クリアまで進めます。開発時のみ提供する読み取り専用の `window.__DEER2__` で状態を観測します。製品ビルドにこの窓口は含めません。スマートフォン実機のSafari / Chromeでの確認は別途必要です。

スマートフォンで試す場合は `npm run dev:mobile` を使い、同じLANからPCのIPアドレスの5178番へアクセスします。ただしWSL2ではWindows側への転送やファイアウォールの設定が必要な場合があります。通常の `dev` はローカル接続のみです。
