# Spruと鹿。（SpraDeer）

奈良公園が舞台の縦画面ゲーム集。TypeScript / Phaser 3 / Vite / Sass。

- 設計書: SmartSprouts の rooms/Spra/dev/SpraDeer/design.md
- 土台: showcases/deersample2（2026-11-09 に本開発へ移行。試作時のREADME・検証記録は docs/prototype/ に保存）
- キャラクター画像4点（spru・spru-clear・spru-oops・deer）は showcases/deersample/public/assets/ から無加工でコピー。正式な素材の原本は rooms/Spra/Mascot/

## 起動

    nvm use
    npm ci
    npm run dev      # http://127.0.0.1:5180/（Windowsのブラウザから開ける）

## 検証

    npm test
    npm run build

## Spruの6方向歩行（2026-11-09）

- 向き: 入力を60度ずつ6領域（下・上・右下・左下・右上・左上）に分けて切り替える（src/game/facing.ts）。止まると最後の向きの立ち絵。開始時は奥（上）向き。
- 足の動きは、実際に進んだ距離（歩幅）で進める。壁に押しつけても足は動かない。
- 画像: 斜め4方向は Mascot の walk 画像、真正面・真後ろは同フォルダの4コマ横並びシートを、scripts/build-spru-walk.py で切り出して public/assets/spru-walk/ に書き出す（原本は無加工。大きさは斜めの立ち絵にそろえる）。再生成: python3 scripts/build-spru-walk.py（Pillow必要）
- 既知の課題: 正面の再生成版も、左足前が3コマ続き左右交互になっていない（確認用レビューで判明）。暫定で、手足の組が正しい2コマと中立コマだけを使って交互にしている。理想は「左足前＋右腕上／中立／右足前＋左腕上／中立」の4コマ＋直立の立ち絵。再生成したら、スクリプトのシート名と歩きの順を直して再実行する。縁にごく薄い黄緑のにじみ・足元の小さな点があるため、再生成時に透明背景の書き出しを依頼する。
- 6方向の見た目確認: scripts/walk-shots.mjs（開発サーバー起動中に実行、test-results/ に出力）

## 歩く鹿と 1-3（2026-11-09）

- 鹿は道を行き来し、決まった時刻にその場で止まって（もじもじ＋落とす場所の輪）、うんこを落とす（src/game/world.ts の stepDeers）。動きは時間だけで決まるため毎回同じ。鹿に触れても失敗しない。
- 面データ: DeerDefinition（種類・道・速さ・最初に落とす時刻・間隔・回数・予告時間）。1-3 は雌鹿と子鹿の2頭。
- 画像: rooms/Spra/assets/deer/ の4コマ歩行シート（雄鹿・雌鹿・子鹿 × 右向き・左向き）を scripts/build-deer-walk.py で切り出し（背景除去の残りの色点を消す処理つき。共通部品は scripts/spritetools.py）。正面・後ろ向きの鹿は Owner が生成予定。届いたら向きを増やす。
- 見た目確認: scripts/deer-shots.mjs（1-3の予告と落とした直後）。

## 2026-11-09 方針変更: Devil Level 系（予兆なし、イラっとさせる）

Ownerの試遊で「簡単すぎる」と判断。旧 1-1〜1-4 は不採用（Gitの履歴に残る）。旧 1-5 を新 1-1 にして、残りを作り直し中。

- 予兆は出さない。ただし動きは固定で毎回同じ（2回目には必ず攻略できる）。失敗した原因と次の手は結果画面に出す。
- 新しい仕掛け（src/game/world.ts）: 道を完全にふさぐうんこ（block）／ジャンプの着地点で開く穴（trigger: land）／予兆なしの床（silent）／ジャンプすると着地点へ動くうんこ（sliders）／横から突然出てくる壁（walls）。
- 各面は、下からスタートして約5区画（スタート y=3400 → ゴール y=300）。
- 新しい仕掛け（追加）: ゴール前に開く大穴（trigger: y）／近づくと逃げて穴に落とすゴール（goal.moveTo と trigger: goal）／近づくと走ってくるうんこ（sliders の trigger: near）／左右から来て真ん中で閉じる壁（walls の length）／追いかけてくる鹿（chasers）／上から降ってくるうんこ（rain。aim: player なら、影が出た瞬間の足元に落ちる）。
- 面: 1-1 安全そうな道（床のおとり＋歩く鹿＋ゴール前の大穴）、1-2 越えた先が、あやしい（ふさぐうんこ・着地点の穴・動くうんこ・走るうんこ・逃げるゴール）、1-3 とつぜんの壁（壁・走るうんこ・ゴール前で左右から閉じる壁）、1-4 追いかけてくる（鹿が追う＋おとりの穴）、1-5 総仕上げ（ふさぐうんこ→降ってくるうんこと壁→追う鹿→逃げるゴール）。
- モンスター（Mascot 201〜224）は、後半の面で段階的に登場させる予定。素材は歩行コマでなくポーズ集のステッカーなので、静止画を動かす敵として使う。
- ブラウザ確認はヘッドレスの描画が遅く（約6fps）、待ち時間を長くしている。

## 2026-11-12 ステージ2「鹿せんべい配達」（2-1〜2-5）
- ボタンは「せんべいを置く」になり（ジャンプはなし）、ゴールは届け先の鹿。せんべいを持った状態で、届け先の鹿に近づくとクリア。
- せんべいを狙う鹿（delivery.thieves）: sense 以内にせんべい（持つSpru／置いたせんべい）が来ると走り出し、近いほうへ向かう。Spruに触れると取られて失敗（outcome stolen）。置いたせんべいを食べている間（約2.6秒）は動かず、食べ終えると満腹になって、もう追わない。sense 0 の鹿は動かない見分け用（触れると取られる）。
- 面: 2-1 はじめての配達 / 2-2 届け先は、子鹿（動かない鹿7頭を避けて子鹿へ）/ 2-3 横取りしにくる鹿（せんべい3個）/ 2-4 おとりで道をつくる（すきまの鹿5頭、せんべい5個）/ 2-5 群れを抜けて（横取り4頭＋動かない鹿3頭＋降るうんこ＋逃げる子鹿）。
- tests/solve-check.ts は、せんべいが必要な面で「せんべいなしでは解けない」ことも確かめる（2-3・2-4・2-5 は必須）。
- 鹿の正面・後ろ向き画像がまだ無いため、寄ってくる鹿も横向きで描く。
- 開発中は src/progress.ts の UNLOCK_ALL=true で全面解放。公開前に false へ。
